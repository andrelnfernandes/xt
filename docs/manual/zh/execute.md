# 编辑、执行与批处理

## 编辑 Edit (E)

在编辑器中打开文件：优先使用 [配置](configuration.md) 第 1 页中设置的编辑器，否则依次尝试 `$VISUAL`、`$EDITOR`、Debian 与 Ubuntu 的 `editor`，或 `vi`。

默认情况下，编辑器会在 **Xylem 的界面框架内** 打开（**F12** 第 1 页中的 `editor_in_frame = true`），并使用 **Xylem 的配色主题**（`editor_theme = true`）；当编辑器为 `vi`、`vim` 或 `nvim` 时，语法高亮与界面颜色也会与当前主题保持一致。若想将整个终端交给编辑器，请设置 `editor_in_frame = false`；若想保留编辑器自带的配色方案，请设置 `editor_theme = false`。

### 二进制文件与按文件类型指定编辑器

文本编辑器打开图片或可执行程序只会显示乱码甚至损坏文件，因此 `E` 绝不会用文本编辑器打开 **二进制文件**（即开头附近含有空字节、查看器以十六进制显示的文件）。

取而代之的是，当启用了 **Edit binary files with E**（**F12** 第 1 页中的 `edit_binary = true`，快捷键 **I**）时，按 `E` 会使用十六进制/二进制编辑器打开二进制文件：

1. `[editors]` 中匹配到的文件名模式（如有），或
2. **F12** 第 1 页中设置的 **Binary editor**（`binary_editor`，快捷键 **J**）或 `[editors]` 中的 `binary`，或
3. 若留空，则自动使用在 `PATH` 中找到的第一个终端十六进制编辑器：
   - **Linux**：`hexedit`、`heh`、`bvi`、`dhex`
   - **Windows**：`heh`（`winget install ndd7xv.heh`）、`hexedit`、`bvi`

终端十六进制编辑器的运行方式与文本编辑器相同：默认在 **Xylem 的界面框架内** 打开（`editor_in_frame = true`），并使用 **Xylem 的配色主题**（`editor_theme = true`）。对于希望在独立窗口中运行的图形界面十六进制编辑器（Linux 上的 `ImHex`、`GHex`、`Okteta`；Windows 上的 `ImHex`、`HxD`），请在命令末尾加上 `&`（例如 `imhex %f &` 或 `ghex %f &`）：Xylem 会直接后台启动它，而不打开终端框架。

如果您不希望 `E` 打开任何二进制文件（仅在底部状态栏给出提示并建议按 `O` 调用系统程序打开），只需将 **Edit binary files with E** 设为 `no`（**F12** 第 1 页中的 `edit_binary = false`）。

若要为特定类型的文件指定专用编辑器，请在 `config.toml` 的 `[editors]` 表中列出：

```toml
[editors]
"*.png *.jpg *.jpeg *.gif" = "gimp %f &"
"*.md" = "typora %f &"
"*.svg" = ""            # 留空：即使匹配也使用常规编辑器
binary = "hexedit"      # 所有其他二进制文件的后备编辑器
```

每个键都是文件名模式列表，规则与 [Filespec](filespec.md) 相同（不区分大小写）；每个值是一条命令行，其中 `%f` 代表文件路径（若省略 `%f`，文件路径会追加在命令末尾）。按配置文件中的顺序，第一个匹配的键生效。当 `binary_editor` 为空时，`binary` 用于匹配未被任何模式命中的其他二进制文件；其余文件则在常规文本编辑器中打开。

Xylem 没有内置十六进制编辑器，这是有意为之的设计选择：自己开发并维护一个需要大量工作却很少用到，而且手动修改字节极易损坏文件。相反，Xylem 将专门的十六进制编辑器无缝集成在自己的界面框架和配色主题中——如果您不需要这项集成，也可以在 **F12** 中一键关闭二进制文件编辑。

## 执行 eXecute (X)

提示输入命令行，并在当前目录中用 `sh` 执行。在命令中可使用以下占位符：

| 占位符 | 含义 |
|---|---|
| `%f` | 光标下的文件 |
| `%t` | 所有已标记的文件 |
| `%d` | 当前目录 |
| `%%` | 字面量 `%` |

所有路径都会自动加上引号，例如：`tar czf backup.tgz %t`。命令执行完毕后，Xylem 会等待您按 Enter 以便查看输出，随后重新读取已打开的目录。以 `@` 开头的命令不会保存在历史记录中（当启用 `history_skip_at` 时）。

对于需要连续交互的操作，使用 [内置终端](terminal.md)（Alt+X）通常更加方便。

## 批处理 Batch (Ctrl+B)

先提示输入要创建的文件名（按 F2 可 [选择文件夹](picker.md)），再提示输入行掩码，然后为每个已标记的文件写入一行。可用参数：

| 参数 | 含义 |
|---|---|
| `%f` | 完整路径 |
| `%d` | 所在目录 |
| `%n` | 文件名 |
| `%b` | 不含扩展名的文件名 |
| `%e` | 扩展名 |
| `%s` | 大小 |

小写参数会自动加上适合 shell 的安全引号（如 `convert %f %b.png`）；大写参数则输出纯文本，适合生成列表（如 `%N;%S`）。若文件名为 `.sh` 结尾，会自动添加 `#!/bin/sh` 并赋予可执行权限（可用 `X` 运行）。不会覆盖已存在的文件。

## 历史记录

在任何提示行中，按 ↑ 和 ↓ 可调出之前的输入记录。每种提示行（Filespec、目标路径、Log、eXecute 等）都有各自独立的历史记录，保存在 `~/.local/state/xylem/history.toml` 中；由于其中可能包含您输入过的命令，该文件仅对您本人可读。
