# Git

XTree 和 ZTreeWin 中都没有 Git 功能，因此它默认处于关闭状态：可通过 F12（第 1 页，“Git commands”）或在 [配置](configuration.md) 的 `[options]` 下设置 `git = true` 来开启。此功能需要系统已安装 `git` 程序。

## Git 菜单 (Ctrl+G)

按 Ctrl+G 会在底部状态栏打开 Git 菜单；接着按相应字母选择操作：

- **S**tatus（状态）、**L**og（日志）、**D**iff（与 HEAD 对比：同时包含已暂存和未暂存的更改，带颜色高亮）以及 **B**lame（逐行追溯）会在 [查看器](viewer.md) 中打开，并支持搜索；
- **G**raph（提交图）：`git log --graph --decorate --oneline --all`，显示所有分支最近的 1000 个提交，使用 Git 自己的颜色（每条分支线一种颜色），同样在查看器中打开；
- **A**dd（暂存）与 **U**nstage（取消暂存）；
- **C**ommit（提交）会像 `git commit` 一样打开 Git 自己的编辑器。

这些命令作用于当前列表中已标记的文件，若无标记则作用于光标下的文件；在目录树中则作用于当前目录。Status 与 Graph 始终针对整个仓库。对于 push、pull 等需要联网的命令，请使用 [执行](execute.md)（`X`），例如输入 `git push`。

## 文件列表中的状态标记

文件列表会在每个文件名前面用 `git status --short` 的两个字符显示其状态：`M ` 表示已暂存的修改，` M` 表示已修改但未暂存，`A ` 表示新添加，`??` 表示未跟踪，`R ` 表示已重命名。未修改的文件显示为空白。每当 Xylem 完成文件操作后、按 F3 刷新后，以及每隔 10 秒（以便捕捉在其他终端中执行的提交），都会自动重新读取 Git 状态。

## 查看器中的 Diff

在查看器中，按 **D** 会显示该文件自上次提交以来的更改（即带颜色的 `git diff HEAD`），再次按 **D** 则返回文件原内容并保持在同一位置。底部状态栏仅在文件确有更改时才会显示“Diff”提示；按 **E** 依然可以编辑文件，返回时 diff 内容会自动更新。

## 不是你创建的仓库

仓库的 `.git` 可以指定由 Git 运行的命令，而下载或解压得到的文件夹会带着它的 `.git`（`git clone` 不会带来）。因此，文件标记以及 Status、Log、Graph、Diff 和 Blame 不会运行其中任何命令：不运行钩子、`core.fsmonitor`、外部差异工具、文本转换或签名验证。代价如下：

- 定义了自己的过滤器的仓库（例如使用 `git-crypt`）在这里没有标记，也没有 Status、Diff 和 Blame，并会显示说明原因的消息。Log 和 Graph 仍可使用。全局配置中的过滤器（例如 Git LFS）被视为可信。
- 文件有改动但没有新提交的子模块不会显示为已更改。

Add、Unstage 和 Commit 是你主动发出的请求，遵循仓库的配置：它们可能运行配置中指定的命令。

### 受信任的文件夹

默认情况下没有任何内容受信任：所有仓库都被视为有敌意。若要让某个文件夹中的仓库使用其全部配置（例如 `git-crypt` 或你自己的差异工具），请在 **Trusted Git folders**（**F12** 第 1 页的 **K**）中添加该文件夹，文件夹之间用 `;` 分隔：

```
~/projects; /work/code
```

在配置文件中它是一个列表：`git_trusted = ["~/projects", "/work/code"]`。文件夹须为完整路径或位于 `~` 下，并涵盖其下的所有内容。指向外部的链接不会带上信任。

**危险：** 在受信任的文件夹中，只要进入仓库，Git 就会以你的权限运行它指定的命令。切勿将他人的任何内容解压或下载到其中，也不要信任 `~` 或 `/`，因为它们包含你下载的内容。
