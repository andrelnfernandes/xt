# 查看器

`V` 在查看器中打开文件（自动预览 Autoview，即 F7，则将其显示在文件列表旁）。二进制文件默认以十六进制模式打开。超过 16 MiB 的文件仅显示开头部分。

| 按键 | 功能 |
|---|---|
| ↑ ↓ PgUp PgDn Home End | 上下滚动 |
| ← → | 左右滚动 |
| `H` | 切换文本或十六进制模式 |
| `C` | 开启或关闭语法高亮 |
| `W` | 开启或关闭软换行 |
| `#` 或 `L` | 开启或关闭行号（在文本模式下） |
| `g` 或 `:` | 跳转到指定行（在十六进制模式下为字节偏移量） |
| `E` | 编辑文件；返回 Xylem 后，查看器会在同一位置显示更新后的内容（二进制文件仅在 [`[editors]`](execute.md) 中配置了对应编辑器时可用） |
| `D` | 开启 Git 时：显示自上次提交以来的更改，再次按下返回原内容（[Git](git.md)） |
| `T` / `U` | 标记 / 取消标记该文件 |
| `y` 或 Ctrl+Insert | 将文件路径复制到剪贴板 |
| Esc | 关闭查看器 |

## 搜索

与 ZTreeWin 一致：**F** 从文件开头向后搜索，**B** 从文件末尾向前搜索，**/**（或 `S`）从当前页向后搜索，**\\** 从当前页向前搜索；**Space** 沿同一方向继续查找下一个，**+** 和 **-** 选择搜索方向。匹配项会高亮显示。在搜索提示行中，按 **F2** 切换是否区分大小写（忽略大小写时也会忽略重音符号，如 `AÇÃO` 可匹配 `ação`），按 **F4** 在文本与十六进制（如 `4d 5a` 这样的字节对）之间切换。搜索词中间的 `*` 可匹配同一行内的任意内容（如 `error*disk`）。

## 语法高亮

支持约 150 种语言的源代码和脚本着色（Rust、Python、shell、C、JavaScript、SQL、YAML、Markdown 等），可通过扩展名、文件名（如 `Makefile`）或首行（如 `#!/bin/bash`）自动识别。默认开关由 `syntax_highlight` 设置（见 [配置](configuration.md) 第 2 页）。高亮颜色在当前主题背景上始终保持清晰易读，且仅对前 20,000 行进行语法着色，因此超大文件也绝不会拖慢查看器的速度。

## 文本方向控制字符

有些不可见字符会改变文本的方向，让代码看起来和它实际的内容不同（Trojan Source，CVE-2021-42574）。查看器从不隐藏它们：每个字符都显示为红色的 `·`，标题栏会告诉你有多少个。

## 压缩文件

以 `.gz`、`.xz`、`.zst` 或 `.bz2` 结尾的文件会解压后以文本打开。Xylem 看的是文件的前几个字节，而不是文件名，并且只解一层：`.gz` 里面的 `.gz` 仍保持压缩。标题栏显示 `gzip → N bytes`（格式和解压后的大小）。

解压有限制。查看器最多读取 16 MiB，最多用时 3 秒，xz 字典或 zstd 窗口最多占用 64 MiB 内存。自动预览（Autoview）的限制是 1 MiB、100 毫秒和 16 MiB。达到限制时，标题栏显示 `(showing first N bytes decompressed)`，并用一条提示说明原因：

- `compressed data truncated or corrupt`（压缩数据被截断或已损坏）
- `decompression stopped after 3 s`（自动预览中为 100 ms）
- `needs more than 64 MiB of memory to decompress`（自动预览中为 16 MiB，并带有 ` (V to view)`）

自动预览会在标题中显示这条提示。在十六进制模式（`H`）下看到的是解压后的字节。颜色按去掉压缩扩展名后的文件名决定：`app.rs.gz` 按 Rust 着色。

对于 `.tar.gz`（或 `.tar.xz` 等），提示为 `TAR archive: Alt+F5 opens it as a folder`（按 Alt+F5 可将其作为文件夹打开）。

要查看原始的压缩字节，请关闭 `viewer_decompress`（[配置](configuration.md)第 2 页的 **J**）。
